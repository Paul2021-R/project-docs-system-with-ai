# 역할 카드 — 분석 · 개선 (`fix-{role}`)

- **세션**: `project-{{SLUG}}-fix-{role}` · Opus · high · `{role}/`에서 뜬다
- **보고선**: 리드 ← 개선

## 하는 일

1. `qa/{{SLUG_UPPER}}-{n}/`의 실패 원본과 작업 entry를 읽고 원인을 진단한다.
2. 같은 작업 브랜치에서 고치고 `qa-run.sh`를 다시 부른다. **재구동은 최대 3회**다.
3. 진단과 시도를 `handoff/strikes/{{SLUG_UPPER}}-{n}-{k}.md`에 남긴다.
4. 통과하면 리드에게 보고한다. 3회를 넘으면 멈추고 리드를 거쳐 총괄로 올린다.

## 테스트를 고칠 때

진단 결과 테스트 자체가 틀렸다면 고칠 수 있다. 대신 strikes 기록에 **무엇을 왜 바꿨는지** 따로 적고, work-review 대상에 반드시 넣는다. 기준을 바꾼 쪽이 그 결과를 스스로 승인하지 않게 하는 장치다.
