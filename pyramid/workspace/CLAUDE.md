# {{PROJECT_NAME}} — 공통 룰

이 워크스페이스에서 뜨는 **모든 세션**이 읽는 룰이다. 역할별 룰은 각 폴더의 `CLAUDE.md`, 역할의 권한과 금지는 `project-docs/roles/`에 있다. 이 파일은 짧게 유지한다. 모든 세션이 이 파일을 맥락 비용으로 안고 시작한다.

## 0. 나는 누구인가

- 세션 이름은 `project-{{SLUG}}-{역할}`이다. 내 역할은 띄워진 에이전트(`--agent`)와 내가 서 있는 폴더가 정한다.
- 세션을 시작하면 `project-docs/roles/{내 역할}.md`를 먼저 읽는다.
- 사람 호칭은 **Paul**이다. Paul은 되돌리기 어려운 결정만 본다. 그 밖의 판단은 자기 층에서 끝낸다.

## 1. 층과 보고선

```
Paul ← 총괄(chief) ← 리드(lead-*) ← 실행(exec-*) · 개선(fix-*)
```

- 지시는 위에서 아래로, 보고와 제안은 아래에서 위로만 흐른다. 층을 건너뛰지 않는다.
- **Paul에게 올리는 것**은 총괄만 한다(`handoff/to-paul/`). 대상은 계약 변경 · 외부 서비스 계약 · 가격 · 공개 범위 · production 적용 · 공유 인프라 변경이다.
- 되돌릴 수 있는 결정(라이브러리 · 내부 구조)은 그 층이 정하고 기록만 남긴다.

## 2. 파일마다 쓰는 쪽은 하나

세션 여럿이 같은 파일을 고치면 서로의 수정을 조용히 덮어쓴다. 그래서 공유 공간은 쓰는 쪽을 하나로 정한다.

| 위치 (`project-docs/`) | 쓰는 쪽 |
|:--|:--|
| `contracts/` · `decisions/` · `workitem/REGISTRY.md` · `handoff/orders/` · `handoff/to-paul/` | 총괄 (리드 앞 지시는 해당 리드도 실행 · 개선 앞으로 쓴다) |
| `handoff/requests/` | 보고하는 쪽이 새 파일로 |
| `handoff/strikes/` · `qa/` | 개선 역할 · QA 스크립트 |
| `status/{역할}.md` · `work-journal/**/{YYYYMMDD}-{역할}.md` | 그 역할만 |
| `ops/` | infra 리드만 |

- 메시지는 **한 건에 한 파일**이다. 기존 파일을 고치지 않고, 답장도 새 파일로 쓴다.
- 🚨 공유 파일은 **자기 저장소 밖**(`{{WORKSPACE_ROOT}}/project-docs/`)에 절대경로로 쓴다. 백그라운드 세션은 파일을 고치기 전에 자기 worktree로 옮겨 가므로, 저장소 안에 쓴 공유 파일은 병합 전까지 다른 세션에 보이지 않는다.

## 3. 작업 번호와 git

- 작업 번호는 `{{SLUG_UPPER}}-{n}`이다. **총괄만 발급**한다(`workitem/REGISTRY.md`). 동시에 번호를 뽑으면 같은 번호가 두 번 나온다.
- 작업 항목의 일정 · 상태는 Phronesis에서 관리하고, 항목 본문에 `{{SLUG_UPPER}}-{n}`을 적는다.
- 브랜치: `{type}/{YYYYMMDD}-{{SLUG_UPPER}}-{n}` (`feature` · `bug` · `chore` · `hotfix`).
- 커밋: `type: 설명` 뒤에 트레일러를 붙인다.

```
feat: 태그 후보 검색 쿼리 추가

Agent-Role: exec
Agent-Session: project-{{SLUG}}-exec-server
```

- `Agent-Role`은 `chief` · `lead` · `exec` · `fix` 중 하나다.
- 세션은 **작업 브랜치만 push**한다. `develop` 병합은 work-review 통과 후 총괄이, `main` 병합은 Paul이 한다. 강제 push와 `main` 직접 커밋은 하지 않는다.
- 배포 태그 · 이미지 태그 같은 GitOps 값은 AI가 고치지 않는다.

## 4. 테스트와 실패

- 테스트와 합격 기준은 **리드가 설계 단계에서 먼저** 쓴다. 실행자는 테스트 파일을 고칠 수 없다(훅이 막는다).
- 실행자는 빌드 · 타입 · 린트 오류는 스스로 고친다. 그다음 `project-docs/scripts/qa-run.sh`를 **1회** 부른다.
- 결과가 **테스트 실패**면 고치지 않고 멈춘 뒤 리드에게 보고한다. 리드는 개선(`fix-*`)을 띄운다. 개선은 재구동 최대 3회이고, 넘으면 총괄로 올린다.
- 결과가 **환경 실패**면 infra 리드에게 보고한다. 개선 역할로 보내지 않는다.
- 개선이 테스트를 고쳤다면 `handoff/strikes/`에 따로 기록하고 work-review 대상에 넣는다.

## 5. 작업 저널

- 맡은 지시 하나를 끝낼 때(완료 · 개선 이관 · 막힘 보고) `project-docs/work-journal/{YYYY}/{MM}/{YYYYMMDD}-{역할}.md`에 절을 덧붙인다.
- 맨 위에 `## 미완 / 다음`을 두고, 각 절은 `**결론**:`부터 쓴다. 이미 쓴 절은 고치지 않는다.
- 커밋한 뒤 저널을 쓰지 않고 끝내려 하면 Stop 훅이 막는다.

## 6. 하지 않는 것

- `.env` · `secrets/` · 키 파일을 외부 리뷰어(opencode)나 문서에 넘기지 않는다.
- 다른 역할의 저장소를 고치지 않는다. 필요하면 `handoff/requests/`로 요청한다.
- 문서 본문은 `~이다` 단정형으로 쓴다. 틀렸던 내용을 다시 적어 부정하지 않고, 확정값만 적는다.
